# 手动初始化与个性化隔离设计

## 背景

仓库当前已经提供 `scripts/init_profile.py`，但它只复制模板。模板内直接包含全身 A/B、固定动作和四周启动期，GIF 展示也直接使用一份固定的 `current-workout.js`。朋友 Fork 后容易把作者的个人训练结构误认为通用处方。

本次改动要让仓库成为可复用的健身教练基础，而不是作者个人计划的公开副本。

## 目标

- 用户主动说“初始化健身教练”后，由 AI 完成首次设置。
- 初始化结果来自新用户自己的目标、条件和限制，不继承仓库作者的训练结构。
- 首次使用不要求用户手动编辑 Markdown、JSON 或 JavaScript。
- 个人档案、训练计划、训练记录和当前 GIF 训练卡不进入 Git。
- 仓库保留公开 GIF 素材来源和定制说明，方便用户为自己的动作补充映射。
- 已有训练数据默认不覆盖。

## 不做的事

- 不制作图形化安装程序或独立应用。
- 不要求用户注册额外平台。
- 不自动诊断疾病或生成康复处方。
- 不把所有可能动作的 GIF 收录进仓库。
- 不在缺少必要信息时猜测精确重量。

## 首次使用流程

1. 用户 Fork 或下载仓库，并在支持项目文件操作的 AI 工具中打开项目目录。
2. 用户主动说“初始化健身教练”。普通的健身咨询不会擅自创建本地档案。
3. AI 检查 `user-data/`：
   - 不存在或仍为空模板时，进入初始化；
   - 已包含有效档案或训练记录时，停止并说明不会覆盖；
   - 用户明确要求重新初始化时，先提示现有数据会被替换，并建议备份。
4. AI 一次询问并等待用户回答：
   - 主要训练目标；
   - 训练经验；
   - 训练地点和可用器械；
   - 每周现实训练次数和单次可用时长；
   - 当前疼痛、旧伤或动作限制；
   - 年龄、身高、体重为选填项，不阻塞初始化。
5. AI 先运行初始化脚本建立空白、合法的数据结构，再把用户明确提供的信息写入个人档案和状态文件。
6. AI 根据用户条件生成第一阶段计划。计划必须解释选择依据，并包含频率、动作顺序、组数、次数范围、选重方法、强度目标和安全边界。
7. AI 生成本地 GIF 训练卡；没有可靠映射的动作显示文字卡，不用相似但错误的 GIF 代替。
8. AI 运行状态校验，并向用户说明初始化结果和下一步用法。

## 数据与文件设计

### 公开模板

`assets/starter-profile/` 继续作为初始化来源，但改成中性结构：

- `PROFILE.md` 保留字段说明和空值；
- `CURRENT-STATE.json` 保留合法的空状态；
- `CURRENT-PLAN.md` 只保留计划字段和生成要求，不包含全身 A/B 或具体动作；
- 示例内容必须显式标注为示例，不能表现为用户的下一次训练。

### 本地个性化数据

以下内容属于新用户自己的数据，并保持在 `.gitignore` 覆盖范围内：

- `user-data/PROFILE.md`；
- `user-data/CURRENT-STATE.json`；
- `user-data/CURRENT-PLAN.md`；
- `user-data/sessions/`；
- 当前 GIF 训练卡数据。

GIF 页面本身和通用动作映射可以提交。当前训练卡改为本地生成文件，仓库只提供不含个人处方的示例或空白回退数据。页面缺少本地训练卡时，应提示用户先完成初始化，而不是显示作者计划。

### GIF 素材与定制入口

仓库新增一份简短的 GIF 定制说明，并从 README 和可视化扩展中链接过去。说明至少包含：

- 素材仓库：[ExerciseGymGifsDB](https://github.com/JahelCuadrado/ExerciseGymGifsDB)；
- 当前固定使用的版本 `v1.1.0`，避免上游变化导致已有动作突然失效；
- 当前数据接口基址 `https://cdn.jsdelivr.net/gh/JahelCuadrado/ExerciseGymGifsDB@v1.1.0/api/en/exercises`；
- 如何在素材仓库中找到动作的 canonical ID；
- 如何把中文动作名、canonical ID 和必要的中文提示加入 `extensions/exercise-visualizer/exercise-map.js`；
- 如何验证接口返回动作信息和 `gifUrl`；
- 找不到准确动作时保留文字卡，不用近似动作冒充；
- 素材归属和许可提示。

仓库不复制整套 GIF 文件，也不把远程素材变成个人训练事实。通用动作映射可以提交；由个人计划生成的“本次训练卡”继续保持本地化并忽略提交。

## Skill 行为

`SKILL.md` 增加明确的初始化触发语和写入流程。初始化完成后，日常训练仍按既有流程读取个人档案、状态、计划和近期记录。

训练计划不再默认固定为全身 A/B。AI 可以在适合新用户时选择全身 A/B，但必须根据目标、经验、频率、时长、器械和动作限制说明原因。不同条件可以生成其他结构。

`AGENTS.md` 在读取个人文件前先判断是否已初始化，避免文件不存在时直接失败。

## 初始化脚本

`scripts/init_profile.py` 仍负责可重复验证的基础工作：

- 创建 `user-data/` 和空白合法文件；
- 接受可选姓名；
- 默认拒绝覆盖已有数据；
- 保留显式 `--force`，并继续显示数据删除警告。

脚本不独立决定训练结构。训练结构由 AI 在收集用户信息后写入，以避免把少量命令行参数发展成复杂问卷系统。

## README 引导

README 开头增加“第一次使用”：

1. Fork 或下载仓库；
2. 在 AI 工具中打开项目；
3. 说“初始化健身教练”；
4. 回答一次初始化问题；
5. 初始化完成后说“今天练”。

现有全身 A/B 内容移到显式示例区域，或删除会被理解为默认处方的内容。GIF 章节说明训练卡在初始化后从本地个性化计划生成。

## 错误与安全处理

- `user-data/` 已存在：默认停止，不覆盖。
- 回答缺少影响计划的必要条件：只追问缺失项，不先生成计划。
- 用户不提供选填身体数据：保留为空。
- 用户报告当前疼痛或明显身体不适：计划避开相关动作，并按现有安全边界建议必要的专业评估。
- GIF 映射缺失或网络不可用：保留完整文字处方。
- 上游 GIF 链接失效：显示文字卡，并允许用户依据定制说明更换 canonical ID 或素材版本。
- 校验失败：说明具体文件和字段，不把半完成状态称为初始化成功。

## 验收标准

- 新用户在仓库中说“初始化健身教练”时，会先被询问个人条件，随后得到自己的计划。
- 空白初始化结果不包含坐姿推胸、坐姿划船、罗马尼亚硬拉、腿举或固定全身 A/B 等作者计划内容。
- 不同训练频率、器械条件或动作限制能够产生不同计划结构。
- 已有 `user-data/` 时不会被默认覆盖。
- 个性化计划和 GIF 训练卡不会出现在 Git 待提交列表中。
- 未初始化时打开 GIF 页面，不会显示作者的“下一次训练”。
- README 能直接找到 GIF 素材仓库和定制说明；用户可按说明增加一个新动作映射并验证其 `gifUrl`。
- 初始化、状态校验、训练记录和摘要更新的自动测试全部通过，并继续使用临时数据目录。
