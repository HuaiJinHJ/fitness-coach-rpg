# Active Workout 启动链路设计

## 1. 背景

当前项目已经具备长期计划、训练记录、状态摘要和动作可视化，但日常“开始训练”的体验仍然割裂：

- 新对话只有在 `fitness-coach-rpg` 作为当前工作区时才会自动加载 `AGENTS.md` 与 `SKILL.md`；
- 训练前固定询问睡眠、精神和疼痛，增加了每次启动训练的摩擦；
- 聊天窗口会再次输出完整训练计划，随后又打开可视化页面，形成重复信息；
- Codex 可能把 `index.html` 当源码文件打开，而不是交给系统默认浏览器；
- `current-workout.js` 当前更像“计划展示数据”，没有被明确建模成“今天这一场训练的最终执行快照”；
- 当 AI 因当天状态修改组数、RPE 或备注时，聊天里的最终处方与网页训练卡存在分叉风险。

本次优化只解决训练开始前到进入训练页面这一段链路，不提前设计训练中记录、组勾选、休息计时器或训练后复盘交互。

## 2. 产品原则

### 2.1 文件是长期状态，对话是操作界面

长期连续性来自项目文件，而不是某一个聊天线程。

项目内区分两类典型对话：

- **规划对话**：修改训练目标、训练频率、动作结构、阶段安排等，并把最终决定写回长期文件；
- **训练对话**：可以每次新建，只负责读取长期文件和历史数据，生成今天这一次训练。

用户不需要维护一个长期不断续聊的“主训练对话”。关闭对话、换新对话或隔一段时间再训练，都应能仅靠项目文件恢复状态。

### 2.2 计划与本次训练是两个对象

- `user-data/CURRENT-PLAN.md`：长期训练模板 / 当前阶段计划；
- `extensions/exercise-visualizer/current-workout.js`：当前即将执行或正在执行的 Active Workout 快照。

Active Workout 由以下信息派生：

`长期计划 + 历史表现 + 用户本次明确提供的状态信息 = 本次训练`

对本次训练的临时降级或替换默认不修改长期计划。

### 2.3 聊天负责决策，浏览器负责执行

正常训练启动后，聊天窗口不重复展示完整动作列表、组数和注意事项。

聊天只负责：

- 判断今天练哪一套；
- 在用户主动报告异常状态时调整处方；
- 生成 Active Workout；
- 告知训练页面已打开；
- 提醒只有器械占用、重量明显不合适、动作不熟、异常疲劳或疼痛时再回来对话。

浏览器训练页负责完整展示今天最终要执行的内容。

### 2.4 默认尽快开始，而不是固定问诊

“开始训练”不再默认强制询问睡眠、精神和疼痛三项。

默认假设用户没有主动报告会改变计划的异常状态，直接按长期计划与历史记录生成 Active Workout。

只有以下情况才补问：

- 用户主动说“今天很累”“昨晚没睡好”“膝盖不舒服”等，但信息不足以决定如何调整；
- 历史状态文件中存在尚未解除、会影响本次训练的疼痛或异常标记；
- 缺失的信息会实质改变本次训练的安全性或处方。

如果用户在第一条消息中已经提供状态，例如“开始训练，6.5h，一般，无痛”，不得重复追问。

## 3. 目标体验

### 3.1 正常情况

用户在 `fitness-coach-rpg` 项目根目录中新建对话并输入：

```text
开始训练
```

系统应完成：

1. 读取 `SKILL.md`；
2. 确认用户档案已经初始化；
3. 读取 `PROFILE.md`、`CURRENT-STATE.json`、`CURRENT-PLAN.md` 和必要的近期训练摘要；
4. 确定今天的训练结构与基于历史表现的建议；
5. 生成或覆盖本地 `current-workout.js`，其中只保存“今天这次训练”的最终处方；
6. 校验 Active Workout 数据；
7. 使用系统默认浏览器打开训练页；
8. 聊天只回复简短结论，例如：

```text
今天是全身 A，训练页已打开。正常训练不用回这里；器械占用、重量不合适或身体不适时再告诉我。
```

### 3.2 用户主动报告状态

用户输入：

```text
开始训练，昨晚 6.5 小时，精神一般，无痛
```

系统直接把该状态纳入本次训练决策，不再追问，并把最终降级后的 RPE、组数或备注直接写入 Active Workout。

浏览器页面显示的内容必须与聊天中的最终决策一致。

### 3.3 信息不足且确实需要补问

用户输入：

```text
开始训练，今天特别累
```

如果无法仅凭“特别累”安全判断，则只追问真正影响决策的最少信息，例如：

```text
昨晚大概睡多久？有没有头晕、身体不适或疼痛？
```

不机械补问固定问卷。

## 4. 组件职责

### 4.1 `AGENTS.md`

负责入口级规则：

- 健身请求必须先读取 `SKILL.md`；
- “开始训练 / 今天练”等意图进入 Active Workout 流程；
- 不依赖聊天历史作为训练事实；
- 不允许使用 Codex 编辑器打开训练页源码来代替浏览器训练体验。

### 4.2 `SKILL.md`

负责训练启动决策：

- 默认不固定询问睡眠、精神和疼痛；
- 只有信息会改变今天处方时才补问；
- 生成 Active Workout 后，聊天不重复输出完整处方；
- 本次临时调整只写入 Active Workout，不自动修改 `CURRENT-PLAN.md`；
- 用户需要修改长期计划时，明确切换到规划任务并写回长期文件。

### 4.3 `current-workout.js`

从“静态可视化数据”升级为 Active Workout 快照。

至少包含：

- 唯一的 session 标识；
- 生成时间；
- 训练名称 / 计划标签；
- 本次训练状态说明；
- 每个动作独立的组数、次数范围、RPE/RIR 目标和备注；
- 本次训练级别的注意事项；
- `initialized: true`。

不再假设整场训练只有统一的 `sets / reps / rpe`。因为状态降级、动作历史和替换动作都可能导致每个动作处方不同。

### 4.4 浏览器训练页

`extensions/exercise-visualizer/index.html` 从“动作 GIF 查看器”调整定位为“Active Workout 训练页”。

本轮只要求：

- 明确显示今天这一场训练；
- 每个动作显示本次最终处方；
- 显示本次状态调整说明；
- 保留 GIF、动作说明和无 GIF 时的文字卡降级；
- 不新增组勾选、重量输入、休息计时和结束训练按钮。

页面展示的是最终执行结果，不再需要用户回聊天窗口对照另一份完整计划。

### 4.5 浏览器启动脚本

新增一个最小脚本，例如：

```text
scripts/open_workout.py
```

职责仅为：

- 找到 `extensions/exercise-visualizer/index.html`；
- 使用 Python 标准库调用系统默认浏览器打开页面；
- 接收本次生成的预期 `sessionId`，校验训练卡中的 `sessionId` 完全一致；
- 通过 query 参数附加当前 session 标识，降低浏览器复用旧页面或缓存内容导致误判的风险；
- 找不到页面时返回明确错误码和提示。

不依赖 Codex 的 `open_in_codex` 行为，也不新增本地 Web 服务。

## 5. 数据流

正常启动的数据流：

```text
用户：开始训练
    ↓
AI 读取长期资料 / 当前状态 / 历史摘要
    ↓
确定今天训练与基于历史的重量或次数建议
    ↓
如用户主动报告异常状态，则只调整本次处方
    ↓
生成 Active Workout current-workout.js
    ↓
校验数据完整性
    ↓
运行 open_workout.py
    ↓
系统默认浏览器打开 Active Workout 页面
```

长期计划保持不变，除非用户明确提出“调整计划”“以后改成每周三次”等规划请求。

## 6. 错误处理

### 6.1 项目根目录错误

如果当前工作区不是 `fitness-coach-rpg`，导致根目录没有 `AGENTS.md` / `SKILL.md`，本仓库内部无法保证子目录规则自动生效。

README 中继续明确：必须把 `fitness-coach-rpg` 本身作为 Codex 项目打开。

不把规则复制到上级“健身”目录，避免其他项目被误套用。

### 6.2 未初始化

用户说“开始训练”但没有有效档案时，不生成默认训练卡；提示先执行初始化流程。

### 6.3 Active Workout 生成失败

- 不打开旧训练卡冒充本次训练；
- 明确告诉用户生成或校验失败；
- 保留长期计划与历史记录不变。

### 6.4 浏览器打开失败

- Active Workout 已生成时仍保留该文件；
- 回复训练页的本地路径，允许用户手动用浏览器打开；
- 不退回 `open_in_codex` 作为默认替代方案。

### 6.5 GIF 或网络失败

继续使用已有降级策略：保留完整文字处方，不因为 GIF 失败阻塞训练。

## 7. 测试与验收

本轮至少覆盖以下测试：

1. “开始训练”在正常状态下不固定触发三问；
2. 第一条消息已包含睡眠 / 精神 / 疼痛信息时不会重复追问；
3. 用户只说“今天特别累”时，规则允许补问最少必要信息；
4. Active Workout 支持每个动作独立处方，不依赖全局统一 `sets / reps / rpe`；
5. 当天临时降级写入 Active Workout，但不会修改长期计划模板；
6. Active Workout 校验失败时不打开旧训练卡；
7. 浏览器启动脚本能正确解析本地页面并调用系统默认浏览器；
8. 未初始化状态不能生成伪训练卡；
9. GIF 缺失不阻塞文字训练卡；
10. 原有训练记录、摘要更新和数据隔离测试继续通过。

## 8. 本轮明确不做

为了避免在真实训练前凭想象扩展功能，本轮不加入：

- 网页内逐组打勾；
- 重量 / 次数输入；
- 休息计时器；
- 自动完成训练；
- 训练后网页表单；
- 数据仪表盘；
- 把网页升级为独立前端应用或本地服务器；
- 语音控制、摄像头姿态识别或自动计数。

这些功能必须等至少一次真实训练或完整模拟后，根据真实摩擦决定是否加入。

## 9. 成功标准

这轮优化完成后，用户应能形成稳定心智：

- 想修改长期训练方案：进入规划对话；
- 今天要去训练：任意新建训练对话，输入“开始训练”；
- 系统自动读取长期状态并生成今天这次 Active Workout；
- 浏览器训练页成为本次训练的唯一完整执行界面；
- 正常训练时不需要在聊天和网页之间反复切换；
- 聊天只在异常情况或需要改变决策时重新介入。

核心目标不是增加功能，而是把“我要训练”到“我已经进入今天的训练页面”缩短为一条清晰、低阻力、不会信息分叉的路径。
